## Correction found and fixed

The interrupted session left `tests/test_activity_checkpoint.py` hanging: the
Free-tier probe decision omitted the required `clarification` field, so
`SubmissionDraft` rejected it, the room entered `interpretation_retry`, and the
test blocked forever waiting for a `probe` phase that never arrived. The
decision now supplies `clarification: None`, matching the existing suite's
shape.

Fixing that exposed a real product gap. The frontend already renders
`operation.retrying` for questions (`questionLabel` in
`game/src/lib/roomPresentation.ts`), but the backend only set it for
interpretation. A manual "Retry question" therefore showed "Thinking…" instead
of "Trying again…", contradicting specification story 45 ("an admitted retry
described as a retry"). `retrying` is now threaded through
`handle_lifecycle` → `_schedule_question` → `QuestionWork` →
`begin_operation`, mirroring the existing interpretation path.
