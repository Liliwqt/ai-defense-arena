## Correction found and fixed

The synthetic provider router in `tests/test_openrouter_streamlit.py` always
returned `status: 'discussed'` for a coverage assessment. The server correctly
rejects that for a timed-out turn (`backend/defense_session.py:301` requires
`needs clarification`), so any integrated test that exercised an answer timeout
failed with "The AI returned an invalid coverage assessment."

The router now derives the assessment from the transcript's `timed_out` flag via
`assessment_for(context, content)`. This is a test-fidelity fix: the synthetic
model now behaves the way a real model must, instead of masking the rule.
