# Ticket 08 — Android microphone practice

Local source: 859b384 on feature/question-first-room, plus one review fix in the
working tree. Baseline **1f760be** was explicitly confirmed by the user. No
push/deployment or main change. This is code review and offline evidence, not
user acceptance or proof of actual device capture.

The Android shell now declares `RECORD_AUDIO` and asks for it only after the
trusted top page sends an explicit `prepare` intent over a dedicated
`WebMessagePort`. `MicrophonePolicy` gates the grant on foreground state, a
trusted current document, a single-use ten-second arm window, the OS permission
and an exact HTTPS origin with no userinfo, query or fragment. Only
`AUDIO_CAPTURE` is granted; camera, mixed and unknown resource requests are
denied. The web side treats the port as the capability signal, so older shells
and unsupported browsers keep typing instead of showing a mic action that cannot
work.

Denial, revocation, backgrounding, navigation and destruction all stop capture.
Android WebView has no stop-all-media API, so after this WebView has prepared a
mic the Activity unloads the document on background and reloads the trusted URL
on return; the mic never restarts automatically. Permission revocation is polled
every 500 ms because a cached origin grant may skip the permission callback.
Track `mute` is treated as failure alongside `ended`.

## Standards

Independent Standards review against 1f760be found **2 hard findings and 6
judgement calls**.

Hard findings, both in `mobile/README.md`, against `docs/agents/domain.md`
("Use the glossary's terms"):

- L33 says "voice practice"; the glossary term is **Speaking practice**.
- L50 says "ten shared voice minutes"; the glossary term is **Voice allowance**.

Judgement calls, not fixed in this slice:

- `MicrophonePolicy.capturePrepared` is a permanent latch, but its name reads as
  current state. The behaviour is deliberate and tested; the name is not.
- `MicrophonePolicy.request(...)` is a predicate that mutates by consuming the
  intent, so a caller cannot ask "would this be allowed?" without side effects.
- Origin trust exists twice with divergent semantics: `ArenaActivity.trusted`
  compares hosts case-sensitively, `MicrophonePolicy.trusted` case-insensitively.
- The Activity still owns nine audio fields plus a self-rescheduling permission
  check; the policy was extracted but the session state that travels with it was
  not.
- The version bump touches three places (`versionCode`, the user-agent string,
  the README).
- `nativeCapture.ts` repeats the `saveDefenseSummary.ts` port handshake and
  imports `isNativeShell` from the export module (Feature Envy).

Evidence rules hold: `mobile/README.md` limits the claim to source integration
and keeps device permission/capture/background as pending.

## Spec

Independent Spec review against 1f760be found **1 Medium fixed here, 2 Medium
and 1 Low remaining**.

Fixed in this slice:

- **Capture unload destroyed an outstanding file-picker callback.** `onPause`
  runs when `ACTION_OPEN_DOCUMENT` opens; if `mustUnloadCapture()` was true the
  document was replaced with `about:blank`, so `onActivityResult` delivered the
  selection to a destroyed WebView and the file was lost. This broke the
  ticket's "preserve download trust and callback boundaries" requirement.
  `stopAudioDocument` now skips the unload while `fileCallback` is outstanding;
  capture still stops through the background event and `suspend()`.

Remaining:

- **External-frame denial is origin-only.** AC1 says "deny external frames/pages".
  `PermissionRequest` exposes origin, not frame identity, so same-origin
  subframes are granted. This is the API ceiling, and `mobile/README.md` already
  states it honestly. The AC wording is what is imprecise, not the code.
- **`capturePrepared` is never cleared**, so after one successful arm a session
  that switches to typing still unloads on every background. This contradicts
  the README's "Typed-only sessions keep the usual mounted-page behavior" and the
  parent spec's typed-draft preservation. The stickiness is deliberate and
  tested, but the README sentence overstates the typed-only case.
- **Low:** if a page finishes loading while backgrounded, `onPageFinished`
  skips `installAudioPort`, and `onResume` only dispatches the resume event when
  `resumeAfterCapture == null`. Voice stays safely unavailable, but recovery
  needs a reload rather than a fresh explicit action.

No scope creep. The `mute` listener is required by the revocation criterion; the
version bump and JUnit dependency are required by AC4.
