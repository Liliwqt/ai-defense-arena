## Proposed breakdown

1. **Short questions and specific panelist reactions**
   - **Blocked by:** None — can start immediately.
   - **What it delivers:** code, research and mixed defenders receive shared
     guidance for one concise main question and optional reactions recognizing a
     real reason/correction/gap. Existing room behavior, reviewer handoffs,
     citations, reaction timing and inline Streamlit dialogue remain usable.
   - **Acceptance focus:** flexible brevity without rejecting valid longer
     questions; distinct voices and grounded evidence; unchanged empty opening,
     clarification/probe/sufficient-answer handling, conditional advice and modern
     Bisaya language continuity. Existing bounded reactions and request stages
     remain. Verify generation contracts and an authenticated room exchange at
     existing mocked seams; document that mocked prose is not live-quality proof.
   - **Checkpoint:** completes the first runnable local checkpoint with its
     relevant checks and README/project handoff update.

2. **Safe final closing before coaching**
   - **Blocked by:** 01 — Short questions and specific panelist reactions.
   - **What it delivers:** when coaching succeeds, defenders see an optional
     closing by the last reviewer, then coaching. The same request produces both;
     the completed run settles before the presentation interval. Empty/unusable
     optional text skips the closing while valid coaching stays available.
   - **Acceptance focus:** compatible report/snapshot defaults; real final
     resolved-turn context and server-owned reviewer identity; two-sentence/
     300-character bounds and current 4–12-second reading interval; completion
     wording and matching speaking highlight; no next vote/answer clock, added
     question or changed coverage. Reconnect resumes remaining time without a new
     request/replay. Retain transcript/export and inline Streamlit closing.
     Coaching failure/retry, empty history, timeouts, host ending, repeated ready
     updates, restart/closure/stale results, room retention and once-only financial
     settlement stay safe. Targeted mocked contracts, authenticated fake-clock
     flows, React and Streamlit checks travel with this complete feature slice.
   - **Why blocked:** final closing uses the first slice's shared dialogue rules
     and completes the same conversational experience; it is not a separate
     evaluation voice or extra AI stage.
   - **Checkpoint:** second checkpoint is runnable; complete handoff awaits 03.

3. **Integrated defenses and local conversation review**
   - **Blocked by:** 02 — Safe final closing before coaching.
   - **What it delivers:** a reviewed integrated experience with complete mocked
     two-client defenses, responsive local screenshots/previews and a separately
     documented live before/after conversation comparison.
   - **Acceptance focus:** full Python/React suites/build; code and twelve-question
     research/mixed defenses covering vote, answer, clarification, probe/reply,
     timeout, early/budget/coverage completion, retry, reconnect, exact citations,
     transcript, coverage gaps, closing and coaching. Check legacy/empty/invalid
     closing compatibility and existing charging/return regressions. Desktop,
     portrait and landscape keyboard/overflow checks preserve controls and source
     access. Compare the same synthetic sources and answers before/after under a
     safely recorded model/configuration in English and modern Bisaya, covering
     code, empirical/theoretical research and mixed integration. Record unavailable
     credentials as missing live evidence, never a passed check. Update README/
     project handoff and present local evidence for human review.
   - **Why blocked:** it reviews and demonstrates the final closing and shared
     conversation changes together; 01 is already a transitive prerequisite.
   - **Checkpoint:** completes the second checkpoint's integrated handoff. User
     visual/native-language, hosted and installed-device review remain distinct.

## Dependency graph and sizing

01 → 02 → 03. Only 01 is initially unblocked.

The shared request, report, room lifecycle, presentation and test seams already
exist. No standalone prefactoring ticket is justified by current inspection.
Optional closing/report compatibility is added inside 02 alongside real delivery
to defenders, rather than making a backend-only schema ticket. Each implementation
slice remains runnable and includes its own necessary tests; 03 adds complete
integration/live/responsive evidence rather than deferring basic safety to QA.
