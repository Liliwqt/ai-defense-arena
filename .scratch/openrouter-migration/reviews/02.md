## Implemented locally

- Funded research/mixed runs snapshot the confirmed provider policy once per
  run (`run:<run_id>` scope): 5.00 USD default `OPENROUTER_RUN_USD` ceiling
  (bounded 0–100), protected coaching reserve sized to the confirmed question
  budget, and a question limit of ceiling minus that reserve. Unfundable starts
  are rejected before any game-credit commitment or provider dispatch.
- Two-stage GLM-low planner then assigned reviewer: Methodology DeepSeek
  v4.1 flash effort high, Ethics Claude Haiku 5.5 effort medium, Impact Qwen
  3.8 flash bounded `max_tokens: 2048` (no invented named effort), Critical GLM
  5.3 flash effort high; planner output 4096, reviewer output 8192; no
  automatic fallback and fixed settings through retries.
- Plan validation (eligibility/coverage/completion) precedes any reviewer
  dispatch; both stages validate together before question, coverage, history,
  vote/clock or credit commit; a valid completion spends one planner call.
- Every dispatched stage reserves transactionally before the HTTP request;
  known receipts settle once, unknown or stale costs retain the full bound.
  Cancellation between stages, duplicate-work suppression and retained answers
  reuse the existing room ownership guards.
- Operator guidance: `docs/OPENROUTER_SETUP.md` documents the run ceiling,
  funded bundle, snapshot/retry semantics, reservation/settlement and the
  unfundable-start behavior.

## Spec

Findings and resolution:

1. Criterion 5's controlled-clock/two-client funded flow was only exercised
   single-client/single-turn, and the legacy multi-turn suites discard the
   funded client — fixed: the new funded rounds test drives two clients through
   four planner/reviewer turns and completion, and the failed-opening retry
   test evidences fixed settings through a room retry.
2. Mid-run policy fallback: the client could create a missing run allowance at
   first dispatch, after credit commitment and re-snapshotting current
   configuration — removed; a missing snapshot now fails with
   “The defense allowance is unavailable. Contact the operator.” before any
   dispatch, with a dedicated test. Establishment happens only at Start/Retry
   reservation time.
3. Fixed settings through an actual room retry were only evidenced at
   establishment — fixed: the failed-opening retry test lowers
   `OPENROUTER_RUN_USD` after the failure and asserts the retried run keeps the
   5.0 billion nano-USD snapshot ceiling.
4. Coaching-reserve sizing vs retries: the reserve is deliberately sized to the
   confirmed budget plus the fixed coaching overhead (Q8), and the question
   bound to the confirmed budget; retries beyond the confirmed budget surface
   the explicit retained-discussion message rather than silently truncating or
   overspending, as documented in `docs/OPENROUTER_SETUP.md`.
5. Input-size estimate (`2 × content + per-turn/framing bounds`) is an
   approximation at Start; the exact JSON bound is rechecked before every
   dispatch and reserved exactly, so an under-estimate cannot overspend — it
   can only surface the handled allowance-stop path above.
