## Implemented locally

- Funded research/mixed rooms route submission interpretation, clarification,
  probe and probe-reply classification through the speaking reviewer's
  run-assigned model instead of the direct OpenAI client.
  `RunQuestionClient.interaction(panelist)` returns a Responses-shaped facade
  (`ReviewerInteractionClient`) that fixes the run model, per-role interaction
  reasoning and a 2048-token output bound while `backend/question_generator.py`
  keeps ownership of the prompt, schema and validation.
- Per-role interaction reasoning: Methodology/Ethics/Critical
  `{'effort': 'low'}`; Impact Qwen `{'max_tokens': 1024}` — an explicit smaller
  completion budget rather than an invented effort selector.
- Funding uses the existing `run:<run_id>` question limit: reserve before the
  request, settle known usage, retain the full stage bound for unknown, stale or
  cancelled work, never consume the protected coaching reserve. Exhaustion keeps
  the saved submission and blocks paid retries; manual retry reuses the same
  assignment with no double dispatch.
- The `OPENAI_API_KEY` check moved behind `client is None`, so a funded run
  needs no key; direct/code-only paths are unchanged.
- Preserved: chosen-defender permissions, same-question numbering,
  clarification/probe limits, answer/probe drafts, reconnect, direct-answer
  recovery, timeout/pause rules and stale-work guards.
