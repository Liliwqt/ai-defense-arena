# Research answer coaching — local checkpoint

Research and mixed defenses now require a validated coaching card for every
recorded question, including a factual card for a missed answer or an asked
question ended before submission. Unasked future questions do not receive cards.
Code-only and older reports retain their existing summary format.

The server copies original words, speakers, citations and available input
provenance from the accepted transcript. AI suggestions cannot replace those
originals. An actual probe reply receives separate feedback for its own speaker;
a missed probe is not fabricated. Research profile, stage, setting, paper evidence
and accepted discussion remain context for the existing coaching request.

Each card contains specific strengths and improvements, suggested wording and a
practice task. Missing facts use a labeled conditional scaffold. Unanswered
originals have no strength or invented stronger answer. Wording examples must
occur verbatim in the matching contribution. Typed input has no audio measures;
recognized voice text and forwarded duration alone do not establish filler totals,
speaking rate, pauses, accent, tone, pronunciation or psychological confidence.
These instructions and structural checks do not prove live model coaching quality.
[Voice delivery evidence](VOICE_DELIVERY_EVIDENCE.md) now separates accepted
transcript examples, server sample-clock recording duration and AI suggestions
for each original/reply speaker. The current English pilot lacks word timing
and confidence, so rate and linguistic pauses remain explicitly unavailable.

Results uses a question selector with focused, expandable original/improvement
sections. The full transcript remains available; summary downloads retain
accepted originals, separate replies/provenance, completed coaching and status.
The typed Streamlit fallback shares the card contract without voice or financial
compensation features.

Research/mixed room reports freeze source, profile and transcript membership at
discussion end. One overview is followed automatically by sequential groups of
at most three questions, up to the supported 100-question budget. Each request
uses existing admission controls and bounded validation; groups are application
requests, not provider Batch API pricing. This can add requests and cost.

A valid optional closing appears once after the overview using its remaining
reading interval, then Results shows ready cards alongside pending/failed work.
Account/payment screens retain the current task. A failed section never replaces
ready cards; only the host can retry failed work, with a finite allowance (three
attempts by default). Rate/admission limits still apply. Export retains status,
original words, sources, speakers, replies, provenance and ready sections.

Visible Results do not mean financial completion. All required sections must
validate, then the durable completion write must succeed before settlement.
Completion-write retry does not regenerate ready sections or charge again.
Existing eligible unavailable-run recovery and service-interruption policy remain;
paid compensation is once-only and free/voucher runs create no credit award.
Late work after recovery/restart/shutdown cannot replace a terminal outcome.
Partial work remains unfinished for room retention and interruption recovery.

Streamlit generates the same bounded sections after Generate coaching, retaining
ready work and retrying only failed sections within the single-browser session.
It displays closing inline and does not offer live-store compensation. Empty
discussions produce factual guidance without a model call. Standalone complete
report callers remain limited to twelve turns and 64,000 characters; larger room
reports use bounded sections. No durable results archive or audio archive is added.

Offline contracts, mocked authenticated defenses and synthetic browser checks are
separate from actual model quality, hosted/provider and installed-device evidence.
No real AI/speech/payment call or deployment is authorized by this document.
